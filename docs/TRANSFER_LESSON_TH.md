# ยูสเคส 6 · จากโมเดลสู่ผังระบบ

เปิด `transfer.html` เพื่อสำรวจระบบที่เชื่อมต่อไว้ แล้วเขียนเอกสารให้ผู้อื่นนำไปติดตั้งซ้ำได้ ใช้ตัวแก้ไขผังร่วมกับยูสเคส 3 แต่แยกข้อมูลและเป้าหมายกิจกรรม ไม่มีคะแนน

## ความต่างจากยูสเคส 3

ยูสเคส 3 ฝึกออกแบบจากโจทย์ ระบบที่ใช้พอร์ตทางเลือกและแสดงภาพได้อาจเป็นคำตอบที่ถูกต้อง ยูสเคส 6 ฝึกบันทึกระบบที่สำรวจ **พอร์ต สาย และการตั้งค่าต้องตรงระบบอ้างอิง** แม้ผังที่ต่างออกไปส่งภาพได้ ก็ยังต้องแก้เอกสารให้สะท้อนสิ่งที่ต่อไว้ ตำแหน่งวางอุปกรณ์ ลำดับวาดสาย และรหัสเส้นของผู้เรียนต่างกันได้

## วิธีใช้

1. เลือกระบบตัวอย่าง 18 ระบบ (2–4 อุปกรณ์ตามโจทย์ที่ตรวจรับแล้ว) หรือทำระบบให้ภาพตรงเป้าหมายในโหมดฝึกของยูสเคส 2 แล้วกด “ถ่ายทอดระบบ →”
2. สำรวจอุปกรณ์ในแผงระบบอ้างอิง คลิกป้าย C1, C2… ของแต่ละปลายสายเพื่อเปิดโมเดลและโฟกัสพอร์ตนั้น บันทึกว่าตรวจพอร์ตและการตั้งค่าของแต่ละเครื่องแล้ว
3. เพิ่มอุปกรณ์ในผังว่าง เลือก OUT / IN และชนิดสาย แล้วตั้งเครื่องตามที่สำรวจ ไม่มีการสร้างเส้นคำตอบลงผังผู้เรียนอัตโนมัติ
4. เขียนขั้นตอนติดตั้งและตั้งค่าอย่างน้อย 10 ตัวอักษร แล้วกด “ตรวจผังเทียบระบบอ้างอิง”
5. เมื่อสำรวจครบ ผังตรงระบบ ภาพถูกต้อง และมีคำอธิบาย จึงกดยืนยันเอกสารส่งต่อได้
6. ดาวน์โหลดรายงานส่งต่อ JSON หรือใช้เมนูเดิมส่งออกผัง JSON/SVG และพิมพ์/PDF ซึ่งเพิ่มตารางติดตั้งและรายการตั้งค่าอุปกรณ์

เครื่องหมาย “ฉันตรวจ…แล้ว” เป็นการบันทึกโดยผู้เรียน ไม่ใช่ระบบตรวจจับว่าผู้เรียนมองหรือเข้าใจโมเดลจริง ความยาวคำอธิบายไม่ใช่การประเมินความถูกต้องของเนื้อหา ผู้สอนต้องตรวจเหตุผลก่อนใช้กับอุปกรณ์จริง

## ระบบจากยูสเคส 2

ส่งสำเนาพอร์ต สาย สถานะเปิด/ส่งภาพ SOURCE Input และแหล่งภาพเป้าหมายปัจจุบัน ต้องอยู่ในโหมดฝึกและระบบพร้อมแสดงภาพ จึงจะกดส่งได้ ไม่เปลี่ยนพอร์ตเป็นคำตอบตัวอย่างหรือเขียนทับผังยูสเคส 3

ระบบที่ส่งมาล่าสุดแสดงในรายการ “ระบบที่ส่งมา” รองรับโจทย์ปกติ 18 ข้อของยูสเคส 2 ไม่ได้ส่งจากโหมดประเมินหรือจากยูสเคส 4/5 โดยตรง การส่งครั้งใหม่แทนที่สำเนารับเข้าครั้งล่าสุด ควรดาวน์โหลดงานเก่าก่อน แต่ใช้รหัสฉบับใหม่แยกคีย์ผัง จึงไม่เขียนทับผังของสำเนาก่อนหน้า

## การตรวจและเอกสาร

ตรวจจำนวนอุปกรณ์ คู่พอร์ต OUT → IN และชนิดสายแต่ละเส้น สถานะเปิดเครื่องทุกอุปกรณ์ การส่งภาพของต้นทาง SOURCE ของ Vertex และ Input ของจอ พร้อมตรวจภาพจากแหล่งเป้าหมายด้วยกฎจำลองร่วมกัน การเปลี่ยนพอร์ต/สาย/การตั้งค่าหลังตรวจต้องกดตรวจใหม่ การย้ายตำแหน่งอุปกรณ์ไม่ทำให้ความตรงของระบบเปลี่ยน การเปลี่ยนคำอธิบายหรือรายการยืนยันสำรวจทำให้ต้องยืนยันเอกสารใหม่

รายงาน JSON ประกอบด้วยสำเนาระบบอ้างอิง ผังของผู้เรียน รายการสำรวจ ผลเทียบ ตารางสาย L1, L2… และสถานะยืนยัน ไม่มีคะแนน ไฟล์ผัง JSON แบบเดิมเปิดด้วยหน้าเขียนผังได้ ส่วนรายงานส่งต่อเป็นเอกสารรวมสำหรับตรวจและอ้างอิง ไม่ใช่ไฟล์นำเข้าผังแบบเดิม

พิมพ์/PDF เพิ่มตารางต้นทาง / OUT ปลายทาง / IN ชนิดสาย และสถานะเครื่องหลังหน้าผังกับเหตุผล ฉบับที่ยังไม่ยืนยันระบุเป็นฉบับร่าง ไม่ใช่การยืนยันผลฮาร์ดแวร์จริง

## การเก็บงาน

- `av-port-lab.transfer.incoming.v1`: สำเนาที่ส่งมาล่าสุดจากยูสเคส 2
- `av-port-lab.transfer.diagram.v1.<referenceId>.<taskId>`: ผังแต่ละระบบอ้างอิง แยกจาก `av-port-lab.diagram.v1.*` ของยูสเคส 3
- `av-port-lab.transfer.notes.v1.<referenceId>`: รายการยืนยันสำรวจและลายเซ็นฉบับที่ตรวจ/ยืนยัน สำหรับดูว่ายังเป็นฉบับเดียวกัน ไม่มีการเข้ารหัสเพื่อป้องกันการแก้ข้อมูลหรือการรับรองผลการเรียน

บันทึกอัตโนมัติในเบราว์เซอร์เครื่องนี้ เรียกงานเดิมเมื่อกลับมาระบบตัวอย่างเดิมได้ ไม่มีบัญชีหรือการส่งผลให้อาจารย์อัตโนมัติ ดาวน์โหลดเพื่อสำรองหรือส่งต่อให้ผู้อื่น

## กฎอุปกรณ์

ใช้พอร์ตและตำแหน่งเดิมที่ยืนยันจากเอกสาร Vertex ไม่แปลง HDMI ↔ RGB/VGA ไม่เพิ่ม Matrix หรือระบบแยกภาพสองจอ ไม่มีโจทย์ 4-05 ถึง 4-10 ที่ยกเลิกไป เส้นทาง USB-C/อะแดปเตอร์ที่ยังไม่จำลองไม่ถูกเดาว่าผิดหรือผ่าน รูปแบบภาพและสายใช้เงื่อนไขบทเรียนเดิม ไม่แก้สเปกอุปกรณ์จริง

## โครงสร้าง

- `transfer-model.mjs`: ตรวจสำเนาระบบ สร้างระบบตัวอย่าง เทียบผัง ตรวจความพร้อม และสร้างรายงาน/ตารางติดตั้ง ไม่มี DOM
- `transfer-sender.mjs`: ปุ่มส่งระบบจากหน้าฝึกยูสเคส 2
- `transfer-activity.mjs`: แผงสำรวจอ้างอิง การเทียบและยืนยัน ส่งออกและภาคผนวกพิมพ์
- `transfer.css`: รูปแบบแผงอ้างอิงและตารางติดตั้ง
- `diagram-editor.mjs` และ `diagram-*`: ใช้ร่วมกับยูสเคส 3 ผ่านส่วนขยายเฉพาะหน้า คีย์เก็บงานยูสเคส 3 และรูปแบบไฟล์ผัง version 1 คงเดิม
- `index.html?device=<id>&port=<portId>`: ลิงก์เปิดโมเดลและเลือกพอร์ตที่อยู่ในอุปกรณ์นั้นเท่านั้น

ทดสอบ `node --test tests/transfer.test.mjs` พร้อมชุดทดสอบเดิมทุกยูสเคส และทดสอบการส่งระบบจริง การดูโมเดล การเขียนผังและดาวน์โหลดรายงานในเบราว์เซอร์
